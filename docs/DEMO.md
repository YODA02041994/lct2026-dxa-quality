# Демонстрационный сценарий

Сценарий рассчитан на 5 минут. Его можно пройти на прототипе (https://docsemenov.ru/dxa/) или на локальном контейнере.
Данные — архив постановщика «Для теста.zip» (3 снимка) либо любой набор DICOM денситометрии.

Запись прохождения шагов 1–3 на прототипе: https://docsemenov.ru/dxa/files/dxaqc_demo.gif

## Подготовка (локальный вариант)

```bash
git clone https://github.com/YODA02041994/lct2026-dxa-quality && cd lct2026-dxa-quality
./run.sh build          # скачивает веса из Release и собирает образ dxaqc
./run.sh serve          # страница http://localhost:8000, Swagger http://localhost:8000/docs
```

## Шаг 1. Загрузка исследования через веб-страницу

1. Открыть страницу сервиса.
2. Перетащить `Для теста.zip` или три файла `.dcm` в поле загрузки, нажать «Проверить».
3. Появляется таблица: 3 файла, 0 сбоев, время обработки 3–7 с.

Ожидаемый результат на архиве «Для теста»:

| Файл | Область | Класс | Тип нарушения | Вероятность: контейнер / прототип |
|---|---|---|---|---|
| `CR000000_ПОП.dcm` | поясничный отдел позвоночника | нарушение | Присутствуют посторонние предметы | 1,00 / 1,00 |
| `CR000000_ППОБ.dcm` | проксимальный отдел бедра (R) | нарушение | Некорректная укладка | 0,98 / 0,97 |
| `CR000001_ЛПОБ.dcm` | проксимальный отдел бедра (L) | нарушение | Некорректная укладка | 0,91 / 0,85 |

Прототип работает на сервере с 2 ядрами в экономном режиме (`DXAQC_NETS_PER_FILE=1`: одна сеть из каждого файла весов),
контейнер по умолчанию считает полный ансамбль, поэтому вероятности отличаются на сотые; класс и тип нарушения совпадают.

Под типом нарушения выводятся протокол измерений (угол оси, запасы до краёв кадра, видимость Th12 и гребней)
и совет лаборанту, что исправить при пересъёмке.

## Шаг 2. Объяснение решения на снимке

Нажать «снимок» в строке таблицы. На снимке показаны:

- анатомические ориентиры, найденные сетью (тела позвонков L1–L5, Th12, гребни; вертелы, шейка, диафиз);
- ось позвоночника или диафиза и вертикаль кадра;
- красные рамки посторонних предметов с уверенностью (на `CR000000_ПОП.dcm` — предмет в верхнем левом углу кадра);
- вероятности по каждому критерию с порогами и итоговый вердикт.

## Шаг 3. Таблица официального формата

Кнопки `results.xlsx` и `results.csv`. В таблице строка на каждый входной файл, колонки по ТЗ:
`path_to_study`, `study_uid`, `image_uid`, `anatomical_region`, `quality_class`, `violation_type`, `quality_prob`,
`processing_status`, `time_of_processing`; дополнительные колонки — `side`, `duplicate_of`, `error_message`, `details`. Несколько нарушений на одном снимке перечисляются через `;`.
Второй лист `по исследованиям` показывает, какие области исследования нужно переснять.

## Шаг 4. Пакетная обработка в контейнере без сети

```bash
./run.sh batch "Для теста.zip" out --overlays --sr
ls out        # results.xlsx  results.csv  run.log  overlays/  sr/
```

Контейнер запускается с `--network none`: снимки не покидают машину. В `out/overlays` — PNG с разметкой на каждый снимок,
в `out/sr` — DICOM Basic Text SR с текстом заключения для загрузки в PACS, в `run.log` — журнал обработки.

## Шаг 5. API

```bash
curl -F "files=@Для теста.zip" http://localhost:8000/api/analyze        # JSON: run_id, summary, rows[]
curl -O http://localhost:8000/api/runs/<run_id>/results.xlsx
curl http://localhost:8000/health
```

Те же запросы доступны в Swagger (`/docs`).

## Шаг 6. Устойчивость

Положить во входную папку вместе со снимками текстовый файл с расширением `.dcm`, копию одного из снимков
и пустую вложенную папку. Ожидаемый результат: обработка завершается без ошибок; у повреждённого файла
`processing_status = Failure` и текст причины в `error_message`; у копии заполнено поле `duplicate_of`,
вердикт совпадает с оригиналом; число строк таблицы равно числу входных файлов.

## Шаг 7. Режим порогов

```bash
./run.sh batch "Для теста.zip" out_sensitive --mode sensitive
```

Обычный режим настроен на максимум F1 (чувствительность 0,78, специфичность 0,88). Режим `sensitive` поднимает
чувствительность каждого критерия до 0,9 и выше для контроля на потоке, где пропуск нарушения дороже повторного
просмотра. Снимки, у которых вероятность критерия ближе 0,10 к порогу, получают отметку «проверить».
