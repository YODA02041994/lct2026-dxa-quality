# Разбор ТЗ «по полочкам»

Источник: ТЗ организатора — после `scripts/download_data.sh` лежит в `docs/materials/ТЗ_Задача4_ДепЗдрав.pdf`,
текст — `docs/TZ_full.txt` (в git не хранятся). Уточнения экспертов 16.09 — в `03_Вопросы_экспертам.md`.

## 1. Клинический смысл

Денситометрия (DXA) измеряет минеральную плотность кости; по ней ставят остеопороз, считают риск
перелома, оценивают динамику на лечении. Цифра T-score достоверна только при правильной съёмке:
правильная укладка, нужная анатомия в кадре, нет металла и артефактов, корректно поставлена область
измерения. Ошибка укладки → цифра «едет» → ложная динамика → повторное исследование.

Сейчас качество проверяет человек вручную. Заказчику нужен автоматический фильтр на входе конвейера
(ЕРИС), который отбраковывает негодные исследования до врача.

**Это не диагностика остеопороза.** Плотность не считаем. Только качество съёмки.

## 2. Что делает сервис

DICOM-исследование → анатомическая область → «годно / нарушение» → тип(ы) нарушения → строка в таблице.

## 3. Вход

- DICOM **без разметки** (нет ROI, контуров, SR, overlay).
- Исследование = 1–3 изображения: поясничный отдел, правое бедро, левое бедро — в любой комбинации.
- Метаданные можно использовать, но решение не должно от них зависеть.
- Пакетная обработка архива/папки с множеством исследований.

## 4. Критерии качества — 6 штук

### Поясничный отдел позвоночника

| Код (наш) | Критерий ТЗ | По-человечески |
|---|---|---|
| `spine_positioning` | корректная укладка | снизу видны верхние края подвздошных костей, сверху — половина тела Th12 |
| `spine_axis_tilt` | ось выровнена, наклон ≤ 5° | позвоночник вертикален; 6,9° на рис. 2 — брак |
| `spine_artifact` | нет посторонних предметов | косточки бюстгальтера, пуговицы, молнии, клипсы |

### Проксимальный отдел бедра (правое и левое — отдельно)

| Код (наш) | Критерий ТЗ | По-человечески |
|---|---|---|
| `hip_positioning` | правильное позиционирование | в кадре большой вертел, шейка бедра, седалищная кость |
| `hip_rotation` | нет ротации | малый вертел чуть выступает по контуру; гладкий контур — переротация, большой вертел — недоротация |
| `hip_roi_field` | корректность поля ROI | запас ≥ 3 см сверху и снизу, ≥ 2 см сбоку от области интереса |

В разметке организатора позиционирование и ротация бедра — **одна колонка** («позиционирование/ротация»).
Нарушений на одном снимке может быть несколько (multi-label).

## 5. Выход

`.xlsx` или `.csv`, **одна строка = одно изображение**:

| Колонка | Формат | Что писать |
|---|---|---|
| `path_to_study` | String | путь к исследованию/файлу |
| `study_uid` | String | идентификатор исследования из DICOM-тегов |
| `image_uid` | String | идентификатор изображения из DICOM-тегов |
| `anatomical_region` | String | определённая область |
| `quality_class` | Integer | 0 — годно, 1 — нарушение |
| `violation_type` | String | тип или перечень нарушений |
| `processing_status` | String | Success / Failure |
| `time_of_processing` | Float | секунды |

Мы добавляем `quality_score` (0..1) — без него организатор не сможет посчитать ROC-AUC.

## 6. Что сдаём

Обязательно: модель + веса; Docker-контейнер; скрипт сборки и запуска под Linux; **офлайн**, без внешних
сервисов; API пакетной обработки; ≤ 3 мин/исследование; нет необработанных исключений; воспроизводимость;
все версии зависимостей зафиксированы; README + руководство пользователя + руководство по развёртыванию +
описание обучения; презентация по шаблону; демонстрационный сценарий; исходный код.

Дополнительно (баллы сверху): визуализация нарушения (маска/контур/точки/heatmap) отдельной серией;
DICOM SR с текстом; автокоррекция разметки с подтверждением врача; веб-интерфейс.

Промежуточная сдача (п. 7.1 ТЗ): MVP с бинарной классификацией и хотя бы одной областью. Дата в таймлайне
не указана — уточняем.

## 8. Железо финальной проверки

2 × H200 141 GB, каждая в своей ВМ (44 CPU, 256 GB RAM). Мы должны указать минимальную и рекомендуемую
конфигурацию инференса. Картинки 280×300 px — GPU не обязателен; делаем контейнер, который работает и на CPU.

## 9. Инженерная формулировка

1. Классификатор области: spine / hip; для hip — сторона L/R.
2. Multi-label головы: spine — 3 критерия, hip — 3 критерия (в обучении 2, так как позиционирование+ротация слиты).
3. Агрегация в `quality_class`, `violation_type`, `quality_score`.
4. Обвязка: загрузчик DICOM (любая структура папок, дедуп), батч, таблица, Docker, CLI+API, документация.

Данных мало: 252 картинки. Это про предобученный бэкбон, аккуратные аугментации (**без поворотов** для
критерия оси, **без отражений** для стороны бедра), кросс-валидацию по исследованиям и бутстрэп-ДИ.
Для редких критериев (3–10 примеров) — гибрид с геометрическими правилами, а не чистая нейросеть.

## 10. Где реальная сложность

- **Редкие классы.** `hip_roi_field` — 3 и 4 положительных примера; `spine_positioning` — 6.
- **Противоречивая разметка.** Сколиоз/перелом/эндопротез трактованы по-разному, см. `02_Данные_аудит.md`.
- **Нет масштаба.** Критерий поля ROI в сантиметрах, `PixelSpacing` отсутствует во всех файлах.
- **Формат сдачи.** Победит контейнер, который запустился с первого раза и выдал таблицу в ожидаемом формате.
