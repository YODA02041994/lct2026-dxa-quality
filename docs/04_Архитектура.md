# Архитектура решения

Принцип: **мало данных → измерения по снимку и небольшие сети, каждое решение объяснимо**.
В обучающем наборе 252 уникальных снимка, на критерий приходится от 6 до 36 снимков с нарушением. Всё, что можно
измерить, измеряется; сеть применяется там, где признак трудно записать формулой (ротация бедра, посторонние предметы).

## 1. Конвейер

```
 вход: папка или zip с DICOM (любая вложенность)
   │
   ▼
 [1] Загрузчик (loader.py) ─ обход, чтение DICOM, группировка по исследованию,
   │                          копии снимков находятся по хэшу пикселей и считаются один раз
   ▼
 [2] Область (region.py) ─ по ширине кадра: 300 px — поясничный отдел, 280 и 248 px — бедро;
   │                        кадр другой ширины — по уверенности локализаторов ориентиров;
   │                        сторона бедра — по положению костной массы таза
   ▼
 [3] Ориентиры (landmarks.py) ─ ResNet18 + FPN, тепловые карты;
   │                             позвоночник: Th12, L1–L5, гребни; бедро: головка, вертелы, шейка, седалищная кость, диафиз
   ▼
 [4] Измерения и сети (criteria.py, cnn.py)
   │     позвоночник                                   бедро
   │     • укладка: ширина полосы таза у нижнего края,  • укладка и ротация: ось диафиза,
   │       яркость мягких тканей                          ансамбль 10 сетей по кадру и вырезкам
   │     • ось: наклон столба по массе кости,           • поле ROI: запас до краёв кадра в см,
   │       наименьший наклон по третям                    высота кадра в см
   │     • предметы: тонкие яркие линии (top-hat),
   │       3 сети, карта предметов
   ▼
 [5] Критерии (criteria.py) ─ логистическая регрессия по каждому из 5 критериев, 2–4 признака
   ▼
 [6] Вердикт (predict.py) ─ класс, типы нарушений, вероятность, отметка «проверить»
   ▼
 [7] Выход (infer.py, sr.py, viz.py) ─ results.xlsx и results.csv, PNG с разметкой, DICOM SR, журнал
```

Один и тот же конвейер вызывают командная строка (`__main__.py`), HTTP-сервис (`api.py`) и контейнер.

## 2. Модели

| Компонент | Что это | Обучение |
|---|---|---|
| Локализатор ориентиров | ResNet18 + FPN, тепловые карты; 8 ориентиров позвоночника, 11 — бедра | разметка команды на 252 снимках; ошибка 2–5 мм |
| Сети по посторонним предметам | 3 × ResNet18, кадр 320 px | предобучение на 9000 рентгенограмм object-CXR, дообучение на 99 снимках |
| Карта предметов | ResNet18 + FPN, тепловая карта «где предмет» | маски object-CXR; на денситометрии применяется без дообучения |
| Сети по укладке бедра | 7 сетей ResNet18 и EfficientNet-B0 (ImageNet), 3 сети DenseNet121 (веса рентгенограмм грудной клетки TorchXRayVision) | кадр целиком и вырезки вокруг малого вертела, седалищной кости, проксимального отдела |
| Критерии | 5 логистических регрессий | вероятности сетей подаются только как вероятности вне обучения |

Состав ансамблей задаётся в одном месте — `src/dxaqc/cnn.py: CNN_SOURCES`, наборы признаков — `src/dxaqc/criteria.py: CRITERION_FEATURES`.

| Критерий | Признаки регрессии |
|---|---|
| Некорректная укладка (позвоночник) | `bottom_width`, `soft_mean` |
| Не выровнена ось позвоночника | `axis_img_deg`, `axis_min_third` |
| Присутствуют посторонние предметы | `th_frac40_log`, `cnn_artifact`, `om_max_all`, `om_area` |
| Некорректная укладка (бедро) | `shaft_img_deg`, `cnn_hip_pos` |
| Некорректная область интереса (бедро) | `min_cm`, `frame_h_cm` |

## 3. Решающее правило

1. Порог критерия выбран по наибольшему F1 на снимках вне обучения; если наибольший F1 держится на отрезке порогов,
   берётся середина отрезка.
2. `quality_class = 1`, если хотя бы один критерий не ниже своего порога. Типы нарушений перечисляются через `;`.
3. `quality_prob` — наибольшая из вероятностей критериев, приведённых к шкале, где порог критерия равен 0,5:
   `logit(p′) = logit(p) − logit(порог)`. Следствие: `quality_prob ≥ 0,5` тогда и только тогда, когда `quality_class = 1`.
4. Критерий в пределах ±0,10 от порога даёт отметку `needs_review`.
5. Режим `sensitive` заменяет пороги на такие, при которых чувствительность каждого критерия вне обучения не ниже 0,9.

Сколиоз, перелом и эндопротез нарушением укладки не считаются.

## 4. Проверка качества

- кросс-валидация по исследованиям, 5 блоков: снимки одного пациента не попадают в обучение и проверку одновременно;
- 95 % ДИ — бутстреп по исследованиям, 1000 повторов;
- все метрики считаются по предсказаниям вне обучения (`scripts/make_report.py` → `docs/metrics.md`);
- отбор признаков на 6–10 снимках с нарушением не обобщается (вложенная проверка, `docs/08`, эксп. 18), поэтому наборы
  признаков заданы заранее по клиническому смыслу.

## 5. Обвязка

| Часть | Реализация |
|---|---|
| Командная строка | `python -m dxaqc run -i <папка или zip> -o <папка> [--format] [--overlays] [--sr] [--mode]` |
| HTTP-сервис | FastAPI: `POST /api/analyze`, `GET /api/runs/{id}/results.xlsx`, `.csv`, `/overlay/{n}.png`, `/health`, `/docs` |
| Веб-страница | `src/dxaqc/static/index.html`: загрузка файлов, таблица, снимок с разметкой |
| Контейнер | `python:3.12-slim`, PyTorch 2.4.1 для CPU, веса внутри образа; `run.sh` — сборка и запуск |
| Устойчивость | ошибка чтения файла превращается в строку `Failure` с причиной; обработка остальных файлов продолжается |
| Производительность | 3 снимка — 4–15 с на CPU; требование ТЗ — не более 180 с на исследование |

Сервис не обращается к внешним системам. Библиотеки `timm` и `torchxrayvision` нужны только для обучения.

## 6. Формат результата

`results.xlsx` и `results.csv` (UTF-8 с BOM, разделитель `;`, десятичная точка), строка на каждый DICOM-файл.
Значения колонок — из ответов постановщика от 16.09 (`docs/03_Вопросы_экспертам.md`).

| Колонка | Значения |
|---|---|
| `path_to_study` | путь к файлу относительно входной папки |
| `study_uid` | StudyInstanceUID |
| `image_uid` | SOPInstanceUID |
| `anatomical_region` | `Поясничный отдел позвоночника` · `Проксимальный отдел бедра` |
| `quality_class` | 0 или 1 |
| `violation_type` | позвоночник: `Некорректная укладка` · `Не выровнена ось позвоночника` · `Присутствуют посторонние предметы`; бедро: `Некорректная укладка` · `Некорректная область интереса`; несколько — через `;`; нарушений нет — пусто |
| `quality_prob` | вероятность нарушения, 0–1 |
| `processing_status` | `Success` или `Failure` |
| `time_of_processing` | секунды |

Дополнительные колонки: `study_dir`, `side`, `duplicate_of`, `error_message`, `details` (JSON: вероятности критериев,
ориентиры, измерения, протокол, совет, рамки предметов). Второй лист xlsx — сводка по исследованиям.

Масштаб: выгрузка изотропная, около 0,6 мм на пиксель (`docs/02_Данные_аудит.md`).
