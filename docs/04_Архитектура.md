# Архитектура решения

Принцип: **маленькие данные → простой, объяснимый, устойчивый конвейер**, а не большая сеть.
252 картинки 280×300 px, 8 бит. Всё, что можно посчитать геометрически, считаем геометрически;
нейросеть — там, где признак трудно формализовать (ротация бедра, артефакты).

```
 вход: папка/zip с DICOM (любая структура)
   │
   ▼
 [1] Loader ─ обход, группировка по исследованию, дедуп по хэшу пикселей,
   │          два идентификатора (папка + StudyInstanceUID), подсказка из имени файла
   ▼
 [2] Preprocess ─ 8-bit → float, паддинг до квадрата, resize 384, нормализация,
   │              контрастная коррекция (CLAHE — опционально, проверить на CV)
   ▼
 [3] Region head ─ spine / hip_L / hip_R  (маленький CNN + flip-инвариантная проверка стороны)
   │
   ├── spine ──► [4a] Spine QC
   │              • spine_axis_tilt  — геометрия: маска позвоночника → главная ось → угол; порог 5°
   │              • spine_positioning — CNN-голова + эвристика по верхнему/нижнему краю кости
   │              • spine_artifact   — CNN-голова + детектор ярких компактных объектов вне кости
   │
   └── hip ────► [4b] Hip QC
                  • hip_positioning_rotation — CNN-голова (multi-label, 2 выхода)
                  • hip_roi_field            — геометрия: bbox кости → отступы до края кадра
                                               (в относительных единицах, пока нет мм/px)
   ▼
 [5] Aggregate ─ quality_class = any(flags), quality_score = max(p_i) или калиброванная сумма,
   │             violation_type = коды через ';', processing_status, time_of_processing
   ▼
 [6] Output ─ results.xlsx + results.csv, лог ошибок, (опционально) heatmaps/маски в zip
```

## Модельная часть

| Компонент | Выбор | Почему |
|---|---|---|
| Бэкбон | timm: `convnext_tiny` или `efficientnet_b0`, ImageNet-предобучение | 252 картинки — только fine-tuning; лёгкий, быстрый на CPU |
| Головы | отдельные multi-label головы для spine (3) и hip (2) | разные критерии, разные области; общий бэкбон экономит данные |
| Лосс | BCE с pos_weight / focal | дисбаланс 3–17 положительных из ~80–100 |
| Валидация | GroupKFold по исследованию, 5 фолдов, повторы; bootstrap 95 % ДИ | требование ТЗ про утечку и ДИ |
| Аугментации | яркость/контраст, шум, небольшой crop/scale, сдвиг | **без поворотов** (критерий оси), **без отражений** без смены стороны |
| Объяснимость | Grad-CAM на CNN-головах, маски/линии для геометрических признаков | доп. функционал 2.6, слайд «кейсы» |
| Резерв | zero-shot/few-shot через VLM локально — не основной путь | только если хватит времени; офлайн-требование |

Геометрические модули (ось, поле ROI, артефакты) — сначала классический CV на масках (порог + морфология +
PCA/скелет), потом сравнение с CNN на кросс-валидации. Побеждает тот, у кого лучше F1 на редких классах.

## Обвязка

- **CLI:** `dxaqc run --input <dir|zip> --output <dir> [--device cpu|cuda] [--explain]`
- **API:** FastAPI, `POST /process` (zip → результат), `GET /health`, `GET /version`. Только локальные вызовы.
- **Контейнер:** `Dockerfile` на `python:3.11-slim` (CPU) + вариант `nvidia/cuda` (GPU); зависимости пиннуты;
  веса внутри образа; `docker save` архив как запасной путь без интернета.
- **Устойчивость:** каждый файл в try/except → `processing_status = Failure` + причина в лог; воспроизводимость через фиксированные seed и детерминированный инференс.
- **Производительность:** цель ≤ 5 с на исследование на CPU; лимит ТЗ — 180 с.

## Формат результата

`results.xlsx` / `results.csv`, строка на каждый DICOM-файл:

| колонка | пример |
|---|---|
| path_to_study | `Исследования/2.25.1024…/series_003_2_CR/…/CR000001.dcm` |
| study_uid | `1.2.643.5.1.13.13.12.2.77.8252.…` (StudyInstanceUID) |
| image_uid | SOPInstanceUID |
| anatomical_region | `spine` / `hip_left` / `hip_right` |
| quality_class | 0 / 1 |
| violation_type | `spine_artifact;spine_axis_tilt` или пусто |
| quality_score | 0.87 |
| processing_status | `Success` / `Failure` |
| time_of_processing | 0.41 |

Дополнительно: `study_dir` (имя папки — ключ разметки организатора), `duplicate_of` (если файл — копия).

## Структура репозитория (целевая)

```
src/dxaqc/
  loader.py       чтение DICOM, группировка, дедуп        ✅ есть
  labels.py       чтение разметки xlsx                    ✅ есть
  preprocess.py   нормализация, паддинг
  region.py       классификатор области и стороны
  geometry.py     ось позвоночника, поле ROI, артефакты
  models.py       CNN-головы (timm)
  train.py        обучение, CV, метрики с ДИ
  infer.py        пакетный инференс → таблица
  cli.py          `dxaqc run`
  api.py          FastAPI
scripts/          unpack_data, audit_dataset, make_report
docker/           Dockerfile.cpu, Dockerfile.cuda, run.sh, build.sh
docs/             разбор ТЗ, аудит, вопросы, архитектура, USER_GUIDE, DEPLOY, TRAINING
tests/            загрузчик на «Для теста», формат выхода, устойчивость к битым файлам
```
