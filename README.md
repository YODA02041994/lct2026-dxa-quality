# ЛЦТ-2026 · Задача №4 · Контроль качества денситометрии (DXA)

ИИ-сервис, который принимает DICOM-исследование денситометрии и отвечает: какая это анатомическая
область, годен ли снимок для клинической интерпретации, и если нет — какое именно нарушение
укладки/позиционирования/поля сканирования обнаружено.

**Заказчик:** Центр диагностики и телемедицины Департамента здравоохранения Москвы.
**Хакатон:** «Лидеры цифровой трансформации 2026», задача от города №4.
**Призы:** 1 000 000 / 600 000 / 400 000 ₽. **Дедлайн сдачи: 29 сентября 2026, 23:59 МСК.**

> По требованию организатора репозиторий к сдаче **публичный** (открываем 28.09). Поэтому материалы
> организатора (датасет, разметка, ТЗ, шаблон) в git **не хранятся** — их скачивает `scripts/download_data.sh`
> по паролю из чата задачи. Ничего из `data/`, `docs/materials/`, `docs/img/`, `docs/transcripts/` не коммитить.

## Данные

Материалы организатора (14.09) скачиваются, не хранятся в git:

```bash
LCT_PASSWORD='пароль из чата задачи' scripts/download_data.sh   # → data/raw/, docs/materials/, docs/TZ_full.txt
python scripts/unpack_data.py                                     # → data/work/
PYTHONPATH=src python scripts/audit_dataset.py                    # цифры из docs/02
```

- `train.zip` — 100 исследований, 499 DICOM, **252 уникальных изображения** (остальное — дубликаты серий);
- `разметка.xlsx` — экспертная разметка, лист «Калибровка», строка = исследование; **истина — колонки критериев, не «Итог»**;
- `test.zip` — 3 файла «Для теста» для отладки загрузчика.

Закрытый тестовый набор участникам не выдаётся; финальные метрики считает организатор.

## Быстрый старт разработчика

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python scripts/unpack_data.py
PYTHONPATH=src python scripts/audit_dataset.py
```

## Запуск сервиса

```bash
PYTHONPATH=src python -m dxaqc run --input <папка или zip с DICOM> --output <папка результатов>
```

На выходе `results.xlsx` (основной) и `results.csv` (UTF-8 с BOM, разделитель `;`, десятичная точка), плюс `run.log`.
**Строка на каждый файл**, включая дубликаты. Колонки: сначала официальные из ТЗ в исходном порядке
(`path_to_study, study_uid, image_uid, anatomical_region, quality_class, violation_type, quality_prob,
processing_status, time_of_processing`), затем служебные (`study_dir, side, duplicate_of, error_message`).
Битый или не-DICOM файл не роняет обработку: строка получает `processing_status = Failure`, причина — в `error_message`.

> Сейчас вместо модели стоит заглушка (`NullPredictor`: «нарушений нет»). Формат, обход входа, дедупликация и
> обработка ошибок — настоящие; модель подключается в `src/dxaqc/predict.py`.

## Как использовался ИИ

Проект ведётся с ИИ-агентами (Claude Code, ассистент «Йода» на OpenClaw) под контролем врача — капитана команды:
разбор ТЗ и данных, код обвязки, документация, планирование. Клинические решения (трактовка критериев,
проверка предсказаний на снимках) — за врачами команды. Правила для агентов — [AGENTS.md](AGENTS.md),
текущее состояние — [STATUS.md](STATUS.md). Инференс сервиса полностью локальный, без обращения к внешним ИИ-сервисам.
