# DXA-QC — контроль качества денситометрии

Решение задачи № 4 хакатона «Лидеры цифровой трансформации 2026» (постановщик — Центр диагностики и телемедицины
Департамента здравоохранения Москвы).

Прототип: https://docsemenov.ru/dxa/ · описание API: https://docsemenov.ru/dxa/docs ·
презентация: https://docsemenov.ru/dxa/files/DXA-QC_presentation.pdf · веса: [Releases](https://github.com/YODA02041994/lct2026-dxa-quality/releases)

## 1. Назначение, возможности, ограничения

Сервис принимает DICOM-исследования денситометрии (DXA) и для каждого снимка отвечает:

1. какая анатомическая область на снимке — поясничный отдел позвоночника или проксимальный отдел бедра;
2. годен ли снимок (`quality_class`: 0 — норма, 1 — есть нарушение) и с какой вероятностью (`quality_prob`);
3. какие нарушения найдены (`violation_type`, официальные формулировки через `;`).

| Область | Тип нарушения | Что измеряется |
|---|---|---|
| Позвоночник | Некорректная укладка | полоса таза у нижнего края кадра, видимость Th12 и гребней |
| Позвоночник | Не выровнена ось позвоночника | наклон оси по массе кости, наклон самой ровной трети |
| Позвоночник | Присутствуют посторонние предметы | тонкие яркие линии вне столба, карта предметов, свёрточная сеть |
| Бедро | Некорректная укладка | ось диафиза, ансамбль сетей по кадру и вырезкам вертела и седалищной кости |
| Бедро | Некорректная область интереса | запасы от ориентиров до краёв кадра в сантиметрах |

Дополнительно к таблице сервис выдаёт: снимок с разметкой нарушения (PNG-серия), DICOM SR с текстом заключения,
протокол измерений и совет лаборанту, отметку «проверить» для снимков у порога, лист «по исследованиям» (что переснять).

Ограничения:

- обучение и проверка выполнены на снимках одного аппарата (GE Lunar Prodigy Advance); на других аппаратах нужна проверка;
- область определяется по ширине кадра (300 px — позвоночник, 280/248 px — бедро), как подтвердил постановщик; кадр другой ширины
  относится к области по уверенности локализаторов ориентиров (на 252 снимках с изменённым масштабом — 252 верных ответа);
- для трёх критериев в обучающих данных 6–10 снимков с нарушением, доверительные интервалы широкие (см. раздел 9);
- сколиоз, перелом и эндопротез нарушением укладки не считаются; плотность кости сервис не рассчитывает.

## 2. Быстрый запуск

```bash
git clone https://github.com/YODA02041994/lct2026-dxa-quality && cd lct2026-dxa-quality
./run.sh build                                    # веса из GitHub Release → weights/ и сборка образа (интернет нужен один раз)
./run.sh batch in out --overlays --sr             # пакетная обработка папки или zip; контейнер работает без сети
./run.sh serve                                    # веб-страница http://localhost:8000 и Swagger /docs
```

То же без скрипта: `scripts/download_weights.sh && docker build -t dxaqc . &&
docker run --rm -v "$PWD/in:/in" -v "$PWD/out:/out" dxaqc run -i /in -o /out --overlays --sr`.

`in/` — папка с DICOM или zip-архивами исследований (любая вложенность), `out/` — результаты:
`results.xlsx`, `results.csv`, `run.log`, `overlays/*.png`, `sr/*_SR.dcm`. Обработка идёт локально, без сети.

Веб-страница и HTTP-сервис: `docker run --rm -p 8000:8000 dxaqc` → http://localhost:8000 (Swagger — `/docs`).
Работающий прототип: https://docsemenov.ru/dxa/ · демонстрационный сценарий: [docs/DEMO.md](docs/DEMO.md).

## 3. Структура проекта

```
src/dxaqc/        пакет сервиса
  loader.py       обход папок, чтение DICOM, дедупликация по хэшу пикселей
  region.py       область по ширине кадра, сторона бедра
  landmarks.py    сеть-локализатор анатомических ориентиров (ResNet18 + тепловые карты)
  criteria.py     измерения по снимку и логистические регрессии по критериям, протокол и совет
  cnn.py          свёрточные сети: ансамбли по критериям, вырезки по ориентирам, карта предметов
  predict.py      сборка вердикта: пороги, режимы, отметка «проверить»
  infer.py        пакетная обработка, таблица, PNG-серия, DICOM SR
  sr.py, viz.py   DICOM Basic Text SR; рисование разметки на снимке
  api.py, static/ HTTP-сервис и веб-страница
  __main__.py     командная строка: python -m dxaqc run …
scripts/          скачивание данных и весов, обучение, отчёт метрик, экспорт примеров
experiments/      скрипты экспериментов, в том числе отклонённых (журнал 20 экспериментов — docs/05, docs/08)
tests/            автотесты (pytest)
docs/             разбор ТЗ, аудит данных, ответы постановщика, архитектура, журнал экспериментов, руководства
presentation/     презентация (PDF), скрипты сборки и рисунки
tools/labeler/    веб-инструмент разметки ориентиров, которым команда разметила 252 снимка
run.sh            сборка и запуск контейнера одним скриптом
docker/, Dockerfile, docker-compose.yml, requirements*.txt, requirements.lock
```

## 4. Системные требования и зависимости

| | Минимум | Рекомендуется |
|---|---|---|
| Процессор | 2 ядра x86-64 | 8 ядер |
| Память | 6 ГБ | 16 ГБ |
| GPU | не требуется | не требуется (CUDA ускоряет пакеты в сотни файлов) |
| Диск | 5 ГБ (веса 0,9 ГБ; образ 2,8 ГБ, в архиве 1,4 ГБ) | 10 ГБ |
| ОС | Linux с Docker 24+ | то же |

Зависимости: Python 3.12, PyTorch 2.4 (CPU), torchvision, numpy, OpenCV, pydicom, scikit-learn, openpyxl, FastAPI, uvicorn,
декодеры сжатых DICOM (pylibjpeg, pylibjpeg-openjpeg, python-gdcm).
Диапазоны версий — `requirements.txt` и `requirements-docker.txt`; точные версии проверенного образа — `requirements.lock`;
базовый образ — `python:3.12-slim`.

Время обработки: 3 снимка — 7–15 с в контейнере на CPU, 4–6 с на сервере с 2 ядрами в экономном режиме (полный цикл через HTTP);
499 файлов (252 уникальных снимка) — около минуты на ноутбуке с GPU.
Требование ТЗ (≤ 3 мин на исследование) выполняется с запасом на минимальной конфигурации.

## 5. Сборка и запуск контейнера

Скрипт `run.sh` (Linux, macOS; нужен Docker 24+) выполняет сборку и запуск:

| Команда | Действие |
|---|---|
| `./run.sh build` | скачивает веса, если их нет в `weights/`, и собирает образ `dxaqc` |
| `./run.sh batch <вход> <выход> [флаги]` | пакетная обработка папки или zip-архива, контейнер запускается с `--network none` |
| `./run.sh serve [порт]` | HTTP-сервис и веб-страница |
| `./run.sh save [файл]` | выгрузка образа в архив для машины без интернета (`docker load < файл`) |

Те же шаги вручную:

```bash
scripts/download_weights.sh            # 18 файлов, 0,9 ГБ; тег по умолчанию v1.0.0, другой: TAG=… scripts/download_weights.sh
docker build -t dxaqc .                # или: docker compose build
docker save dxaqc | gzip > dxaqc.tar.gz   # перенос образа на машину без интернета: docker load < dxaqc.tar.gz
```

Команды контейнера:

| Команда | Действие |
|---|---|
| `dxaqc run -i /in -o /out` | пакетная обработка папки или zip |
| `… --format xlsx\|csv\|both` | формат таблицы (по умолчанию оба) |
| `… --overlays` | PNG-серия с разметкой нарушения на каждый снимок |
| `… --sr` | DICOM SR с текстом заключения на каждый снимок |
| `… --mode sensitive` | клинический режим порогов (чувствительность ≥ 0,9 по критерию) |
| `dxaqc serve [--port 8000]` | HTTP-сервис и веб-страница |

Переменные окружения: `DXAQC_WEIGHTS` (папка весов), `DXAQC_MODE` (`competition`/`sensitive`), `DXAQC_NETS_PER_FILE=1`
(экономный режим для слабого сервера: одна сеть из файла вместо ансамбля из трёх), `DXAQC_MAX_UPLOAD_MB`, `DXAQC_RUN_TTL_MIN`, `DXAQC_FILES` (необязательная папка материалов, отдаётся по `/files/<имя>`).

Запуск без контейнера: `pip install -r requirements.txt && PYTHONPATH=src python -m dxaqc run -i <вход> -o <выход>`.
Подробно — [docs/DEPLOY.md](docs/DEPLOY.md).

## 6. API

| Метод | Адрес | Назначение |
|---|---|---|
| POST | `/api/analyze` | multipart `files` (один или несколько `.dcm` или `.zip`) → JSON: `run_id`, `summary`, `rows[]` |
| GET | `/api/runs/{run_id}/results.xlsx`, `.csv` | таблица официального формата |
| GET | `/api/runs/{run_id}/overlay/{n}.png` | снимок `n` с ориентирами, осью, рамками предметов и вердиктом |
| GET | `/health` | состояние сервиса, версия, загружены ли веса |
| GET | `/files/{имя}` | материалы решения (презентация, демо-запись), если задана папка `DXAQC_FILES` |
| GET | `/docs` | Swagger |

```bash
curl -F "files=@study.zip" http://localhost:8000/api/analyze
```

Сервис не обращается к внешним системам; загруженные файлы хранятся во временной папке и удаляются через 3 часа.

## 7. Формат входных и выходных данных

Вход: папка или zip с DICOM любой вложенности. Файлы без расширения проверяются по сигнатуре `DICM`. Имя папки верхнего
уровня считается идентификатором исследования. Метаданные DICOM для решения не нужны.

Выход — `results.xlsx` (лист `results`) и `results.csv` (UTF-8 с BOM, разделитель `;`, десятичная точка).
**Одна строка на каждый файл, включая дубликаты.**

| Колонка | Тип | Значение |
|---|---|---|
| `path_to_study` | String | путь к файлу относительно входной папки |
| `study_uid` | String | StudyInstanceUID |
| `image_uid` | String | SOPInstanceUID |
| `anatomical_region` | String | «Поясничный отдел позвоночника» / «Проксимальный отдел бедра» |
| `quality_class` | Integer | 0 — норма, 1 — нарушение |
| `violation_type` | String | типы нарушений через `;`, пусто при норме |
| `quality_prob` | Float | вероятность нарушения, 0…1 |
| `processing_status` | String | `Success` / `Failure` |
| `time_of_processing` | Float | секунды |

Служебные колонки после официальных: `study_dir`, `side`, `duplicate_of`, `error_message`, `details` (JSON: вероятности
критериев, ориентиры, измерения, рамки предметов, протокол, совет, отметка `needs_review`).
Второй лист `по исследованиям`: число файлов, нарушений, что переснять, совет.

## 8. Модель, предобработка, постобработка

Предобработка: чтение пикселей DICOM (сжатые форматы декодируются, 12–16 бит и MONOCHROME1 приводятся к 8 битам со светлой костью),
хэш для дедупликации, область по ширине кадра, сторона бедра по положению таза
(левое бедро отражается в ориентацию правого), приведение к квадрату 320 px без искажения пропорций.

Модель:

1. **Локализатор ориентиров** — ResNet18 + FPN, тепловые карты; 8 ориентиров позвоночника, 11 — бедра; ошибка 2–5 мм.
2. **Измерения по снимку** — ось позвоночника и диафиза по массе кости, запасы до краёв в сантиметрах, полоса таза,
   яркость мягких тканей, тонкие яркие линии (морфологический top-hat).
3. **Свёрточные сети** — 3 сети по посторонним предметам (предобучены на 9000 рентгенограмм грудной клетки object-CXR),
   10 сетей по укладке бедра: кадр целиком и вырезки вокруг малого вертела, седалищной кости, проксимального отдела
   (семь сетей ResNet18 и EfficientNet-B0, три сети DenseNet121 с весами рентгенограмм грудной клетки TorchXRayVision),
   карта предметов (обучена на масках object-CXR, на DXA применяется без дообучения).
4. **Логистическая регрессия по каждому критерию** на 2–4 признаках; пороги выбраны по максимуму F1 на снимках вне обучения
   (если максимум держится на отрезке порогов, берётся середина отрезка).

Постобработка: `quality_class = 1`, если хотя бы один критерий не ниже своего порога. `quality_prob` — наибольшая из вероятностей
критериев, приведённых к общей шкале, в которой порог критерия равен 0,5: `logit(p′) = logit(p) − logit(порог)`. Поэтому
`quality_prob ≥ 0,5` тогда и только тогда, когда `quality_class = 1`;
критерий в пределах ±0,10 от порога даёт отметку `needs_review`. Обучение и воспроизведение — [docs/TRAINING.md](docs/TRAINING.md),
архитектура — [docs/04_Архитектура.md](docs/04_Архитектура.md).

## 9. Метрики

| F1 | 0,762 [0,680; 0,832] |
| Accuracy | 0,859 [0,820; 0,899] |
| Balanced accuracy | 0,835 [0,786; 0,884] |
| Чувствительность / специфичность | 0,778 / 0,893 |

## 10. Известные ошибки и их обработка

| Ситуация | Поведение |
|---|---|
| Файл не читается как DICOM, нет пикселей | строка с `processing_status = Failure`, причина в `error_message`; пакет продолжается |
| Кадр нестандартной ширины | область определяют локализаторы ориентиров, в `details` пометка `region_by = localizers` |
| Кадр без позвоночника и бедра (уверенность обоих локализаторов ниже 0,30) | `Failure`, `unsupported_image` |
| Сжатый DICOM (RLE, JPEG Lossless, JPEG-LS, JPEG 2000) | читается, результат совпадает с несжатым файлом |
| Снимок 12–16 бит или с перевёрнутой шкалой (MONOCHROME1) | приводится к шкале обучающих снимков (8 бит, кость светлая) |
| Дубликат снимка в другой серии | своя строка, результат берётся от первого экземпляра, `duplicate_of` указывает на него |
| Нет весов в `weights/` | сервис сообщает об этом в журнале и отвечает заглушкой «нарушений нет»; `/health` показывает `weights_loaded: false` |
| Архив с кириллицей в именах (cp866) | имена перекодируются при распаковке |
| Недостаточно памяти на слабом сервере | `DXAQC_NETS_PER_FILE=1` |
| numpy 2.x | поддерживается (исправлено обращение `ndarray.ptp`) |

Необработанных исключений в пакетной обработке нет: любая ошибка файла превращается в строку `Failure`.

## 12. Данные и сторонние материалы

Материалы постановщика (снимки, разметка, ТЗ, шаблон презентации) в репозитории не хранятся; участники скачивают их
скриптом `scripts/download_data.sh` с паролем из чата задачи. Сторонние данные для предобучения: набор object-CXR
(JF Healthcare, MIDL 2020, лицензия CC BY-NC 4.0); исходные веса ResNet18 и EfficientNet-B0 — ImageNet (torchvision).
Исходные веса DenseNet121 — TorchXRayVision (Cohen JP, et al., arXiv:2111.00595; библиотека под лицензией MIT), предобучение на открытых
наборах рентгенограмм грудной клетки. Библиотека нужна только при обучении; в сервисе сеть собирается из torchvision.
